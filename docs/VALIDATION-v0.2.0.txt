SMART BOOST EVIDENCE AND LIMITS
Policy checks cover active app families, project/terminal/trading/Office tools,
busy/new/small/visible/Windows processes, inactive browser renderers, controller
and extension exclusions, media uncertainty, custom exclusions, identity
changes, cooldown, capped work, cancellation and exited candidates.
The UI check invokes the real WPF floating-button event with an injected scoped
host and verifies that no main UI or chooser opens. That is UI wiring evidence,
not live user-app optimization proof. The real native trim test uses only a
separate 96 MB helper and verifies every allocated byte afterward. No user app
was trimmed by the test. Read-only Core Audio enumeration also ran on this PC.
These tests do not prove compatibility with every app/tab/project. Trimming a
working set does not deallocate app data and can cause later paging latency.

SECURITY AND COVERAGE LIMITS
No independent security audit, signing, broad hardware matrix, all-scaling,
all-browser, installer upgrade-migration or prolonged soak test was performed.
This is an unsigned local preview, not a one-for-one Advanced SystemCare clone.
Windows integrations are distinguished from implemented features in the map.
There is no malware engine, temperature driver or independent driver updater.
No network listener, ads, telemetry uploads, downloaded code or background
service is implemented. These design choices do not establish complete security.

Core tests use isolated files and synthetic startup entries. Installer tests
compile fixture paths/registry keys into a separate test executable; they do
not install over the normal user application directory. The production
installer has no environment-variable test-root override. Unrelated shortcuts
and unowned fixture data survived reinstall/uninstall.
