QUIETCARE 0.2.0 — LOCAL WINDOWS PREVIEW
Built 23 October 2026

GET STARTED

Run QuietCare-Setup.exe to install for your Windows user, create Start menu
shortcuts, and optionally create a desktop shortcut. Administrator access is
not requested. QuietCare.exe also runs as a portable executable.
Requires Windows 10/11 x64 with .NET Framework 4.8 or later.

WHAT CHANGED

The full-width title strip is removed. Transparent window controls share the
page background, and branding and navigation live in the sidebar. Drag the
sidebar branding or the empty top edge to move the window; double-click there
to maximize/restore. The top-right controls provide settings, minimize,
maximize/restore, and close. The interface uses static navy, cyan, violet and
mint graphics rather than a continuous animated background.

The floating strip shows CPU → GPU → RAM with content-sized width. The native
preview measured 205 x 28 pixels; its width changes slightly with the readings.
Drag its readings to move it. Use the arrow or double-click readings to expand.
Click the left lightning button for DIRECT SMART RAM BOOST. It checks eligible
background processes and shows the result beside the monitor; no chooser opens.
The monitor stays non-activating so clicking Boost does not take focus from your
current app. Right-click for Boost, refresh speed, settings, hide, and exit.

REFRESH SPEED AND RESOURCE USE

Settings provides 100, 250, 500, 1,000, 2,000, 5,000 and 10,000 ms presets and a
custom slider. Changes apply immediately and persist. Faster polling uses more
CPU. A read is skipped while the previous sensor read is still running. Windows
and drivers may update source counters less frequently than your chosen rate.

The compact mode collects CPU/GPU/RAM only. Disk/network collection starts when
you expand the monitor. Network rates are calculated at most once per second;
adapter discovery is cached for 30 seconds. Main summary and tray text update
at most once per second. Numeric widget labels update only when values change.
The main interface is constructed only when opened and released on close to
tray. Sampling stops when both the main window and monitor are hidden, when
only a minimized main window remains, and during system suspension.

Local 20-second monitor-only observations on this 8-logical-CPU PC:
   1000 ms: 0.146% total CPU, 96.9 MB working set (20.02 seconds)
    250 ms: 0.703% total CPU, 97.7 MB working set (20.01 seconds)
    100 ms: 1.601% total CPU, 99.8 MB working set (20.01 seconds)
Fully hidden: 0.000% observed CPU, 52.8 MB working set; polling disabled.
No compact-only rates excluded from this final matrix.
These short local readings are not a universal limit or a battery/long-duration
benchmark. Other workloads were active. See VALIDATION-v0.2.0.txt for scope and raw data.

SMART RAM BOOST: WHAT IT DOES

Boost uses Microsoft's documented EmptyWorkingSet API to ask Windows to trim
resident pages from qualifying idle background processes. It does not kill,
suspend or restart apps, discard/reload tabs, purge the standby list, clear app
data, or change browser settings. There is no periodic automatic RAM cleaning.

The current application family, active browser family, active audio/calls,
Windows processes, visible unminimized applications, and common editor,
terminal, build, Office, trading, VM and media tools are excluded. Additional
protected process names can be added in Settings. Candidate identity is checked
again by the native trim routine. Busy, very new, small or inaccessible
processes are skipped. Media activity is queried without recording audio.
If media activity cannot be verified, no candidate apps are changed.

Browser candidates are limited to idle renderers in an INACTIVE browser with
verified media activity. Browser controllers, GPU/utility processes, extensions
and an entire browser family playing audio are excluded. Windows cannot tell
QuietCare which individual tab contains your project or a form. Consequently,
it protects the whole active browser family rather than promising selective
cleanup of inactive tabs inside that browser. Chrome/Edge Memory Saver is the
appropriate browser-managed option for tab-level memory management; it can
reload discarded inactive tabs, whereas QuietCare does not request tab discard.

Boost observes CPU twice, excludes candidates using more than 20 ms CPU between
snapshots, and trims at most 12 successful candidates with a five-second trim
loop budget. Observation and Windows calls add time around that loop. A 30-second
cooldown prevents repeated trims. Results report available physical RAM before
and after, not a misleading sum of process working-set sizes.

Working-set trimming does not free an application's allocated data. Pages may
be loaded back as soon as the app needs them, with page faults and possible
latency. Lower displayed RAM use is not a guaranteed performance improvement.
The advanced process page remains available for optional manual selection.

OTHER FEATURES

* Startup inventory and disable/restore of current-user Run entries, with
  literal command and registry-type backups and restore collision protection.
* Optional QuietCare launch at Windows sign-in, using the installed/portable
  executable's current location. Enable this after putting it in its final path.
* Preview of old user-temp files, handle-based quarantine, recovery and confirmed
  permanent deletion of individually selected quarantined files.
* Read-only large-file and SHA-256 duplicate-content finders.
* Desktop-app inventory with name/publisher filtering.
* 37 fixed Windows maintenance tool entry points.
* Local hardware/Windows information and latest-900-sample CSV export.
* Power-plan selection with backup and restoration of the original plan.

STARTUP AND WINDOWS INTEGRATIONS

Speed Up > Startup Optimizer directly manages current-user Run entries.
Machine-wide and folder entries are listed read-only; scheduled tasks, Store
apps and other types use Windows Startup settings and the Windows consoles.
"Registered" means a Run entry exists; Windows may already have disabled it.

Security, privacy, Windows/driver/Store updates, disk optimization, services,
tasks, app removal, backup and networking open their named Windows tools.
Windows handles permissions and the changes you choose there. QuietCare does
not contain an antivirus, driver database, VPN, browser-history cleaner, general
registry cleaner, or all modules of Advanced SystemCare Pro.

SCAN previews old temporary files. It does not perform a malware scan or invent
a health score. See FEATURE-COVERAGE.html for the implementation map.

CLEANUP AND RECOVERY

The cleaner scans only the current user's LocalAppData\Temp folder. Eligible
extensions are TMP, TEMP, LOG, ETL, DMP and CACHE; files must be older than seven
days and no larger than 512 MB. It stops at 30,000 entries or 20 seconds and
labels partial results. Links, linked folders, hard links, locked/inaccessible
files, and changed file identities/sizes/timestamps are excluded. Downloads,
browser profiles, documents, cookies and passwords are outside this policy.

Quarantine moves selected files to LocalAppData\QuietCare\Recovery on the same
drive. This does not reclaim storage yet. Review Recovery, restore what you
want, then confirm permanent deletion to reclaim storage. Permanent deletion
cannot be undone. Changed quarantine content and stale selections are rejected.
Restoration never overwrites a destination. Legacy recovery entries without a
verified timestamp can be restored if eligible but cannot be purged by this build.

The duplicate finder examines up to 20,000 entries with a 1 GB hashing budget.
Hashing is cancellable between 64 KB chunks. Results never delete files.

DATA AND UNINSTALL

Settings, local activity log and recovery live under %LOCALAPPDATA%\QuietCare.
Application files install under %LOCALAPPDATA%\Programs\QuietCare.
The X hides the main window to the notification area by default. Right-click
QuietCare's notification icon or the monitor and choose Exit to stop it.
Launching QuietCare again reveals the existing instance.

Uninstall through Windows Installed apps or Start > QuietCare > Uninstall
QuietCare. Restore any startup entries or original power plan you want first.
Uninstall removes the app and its own shortcuts/registration while retaining
settings, recovery and startup backups. Unrelated shortcut targets are preserved.
Its small temporary uninstall helper remains in Temp after it exits.

Advanced SystemCare is not automatically removed. Use its normal uninstaller
from Windows Installed apps after reviewing the features you depend on.

VALIDATION AND SECURITY SCOPE

42 core checks, 20 UI checks, 4 isolated installer lifecycle checks passed.
The live Boost data test trims only an isolated helper and verifies every byte
of its 96 MB allocation afterward. Native UI review includes the redesigned
Care page, compact monitor and maximize/restore. This does not prove all apps,
browser versions, Windows versions, hardware, scaling or accessibility settings.

This is an unsigned preview with no independent security audit. It cannot be
honestly guaranteed 100% bug-free or secure. There are no ads, accounts,
telemetry uploads, network listeners, automatic updaters, downloaded scripts,
plugin loaders, bundled drivers or background services. Windows tools use a
fixed allowlist and trusted system paths. Inventory uninstall strings are not
executed. These are design choices, not proof of complete security.

GPU uses the busiest engine after summing process instances of each engine.
CPU is system busy time; readings may differ from Task Manager's CPU utility.
Missing sensors show unavailable. Temperatures are not supported without a
hardware sensor implementation/driver and are not fabricated.

BUILD FROM SOURCE

In Windows PowerShell from the extracted source directory:
  .\build.ps1
  .\test.ps1
  .\test-ui.ps1
  .\package.ps1
  .\test-installer.ps1
Optional local resource measurement: .\benchmark.ps1 -Seconds 20
Do not interact with QuietCare during the benchmark. A result with
mainUiConstructed=true is not a valid floating-only measurement.

Uses Windows' Framework64 C# compiler; no NuGet/npm restore is required.
Fixtures stay in test-runs for inspection. Installer test paths are substituted
at compile time; the production installer has no test-root environment override.
